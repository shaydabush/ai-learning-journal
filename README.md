## Day 2 – How models are built
- 3 שלבי בניית מודל: Pretraining (ידע מהאינטרנט) → Fine-tuning (פורמט וסגנון של עוזר) → RLHF (מה בני אדם מעדיפים, כולל להודות שלא יודע)
- RAG – נותן למודל את המידע הנכון בזמן השאלה, בלי אימון. מעדכנים קובץ וזהו
- Fine-tuning – מלמד את המודל איך לענות (סגנון ופורמט), לא עובדות
- ניסוי 3 מודלים: Claude המציא קוד קופון (SORRY10), כולם הבטיחו פעולות שאף אחד לא יבצע, Gemini היחיד שביקש מספר הזמנה. במלכודת אף מודל לא המציא מחיר, Claude ניסה לבדוק ב-Shopify עם כלי
- בוחרים מודל לפי: איכות במשימה, עלות, מהירות, חיבור לכלים, פרטיות
- הבחירה שלי לבוט שירות: Gemini – הוביל לפתרון ולא המציא נתונים. את החסרונות (טון רשמי) מתקנים בפרומפט

## Day 5 – APIs & JSON
- API = תוכנות מדברות זו עם זו: URL + Method + Headers + Body ← JSON חוזר
- GET מביא מידע, POST שולח תוכן. קריאה ראשונה: agify מהדפדפן
- קודי סטטוס: 200 הצליח, 4xx הבעיה אצלי, 5xx הבעיה אצלם, 429 יותר מדי בקשות
- Webhook = API הפוך: המערכת מודיעה לי כשקורה אירוע. רוב האוטומציות מתחילות ב-Webhook
- שליפה מ-JSON מקונן: current.temperature_2m. באג נפוץ: זמנים ב-UTC ולא בשעון ישראל
- מפתח API לא נכנס לקוד ולא ל-GitHub. שמרתי אותו ב-Script Properties
- בניתי Google Sheet שקורא ל-Gemini API עם Apps Script ומחזיר תשובה + טוקנים + עלות
- ממצא: ב-Gemini עברית לא יקרה יותר בקלט (6 מול 7). ב-OpenAI היא הייתה יקרה ב-60%. כל מודל נמדד בנפרד
- 94% מהעלות היא פלט. לכן תשובות קצרות חוסכות כסף
- סוכן Gemini "תיקן" לי נוסחה בכך שהחליף את כל הפתרון. תמיד בודקים מה הסוכן שינה
